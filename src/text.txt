1. config

역할: 프로젝트 전반에서 공통으로 쓰이는 설정 관리

예: 포트 번호, DB 연결 정보, 환경변수(.env), 외부 API 키

장점: 설정을 한곳에서 관리하므로 유지보수 쉬움

--------------------------------------------------------------------------------------------

2. controllers

역할: 클라이언트 요청(req)과 응답(res)을 처리하는 실제 실행 로직 담당

보통 **라우트(routes)**에서 컨트롤러를 호출함

단순히 요청 → 서비스 호출 → 응답 반환 흐름을 담당

--------------------------------------------------------------------------------------------

3. db

역할: 데이터베이스 연결 관리

커넥션 풀, 쿼리 실행 함수 등을 정의

DB 관련 로직을 중앙화해서 재사용 가능

--------------------------------------------------------------------------------------------

4. middlewares

역할: 요청과 응답 사이에서 동작하는 중간 처리 로직

인증, 로그 기록, CORS 설정, JSON 파싱, 쿠키/세션 관리 등

--------------------------------------------------------------------------------------------

5. models

역할: 데이터 구조 정의 (DB 테이블 ↔ JS 객체 매핑)

ORM(예: Sequelize)이나 쿼리 빌더 역할을 하기도 함

DB와 직접 소통하는 로직을 여기에 둠

--------------------------------------------------------------------------------------------

6. python

역할: Python 기반 머신러닝/딥러닝 모델 실행 코드

Node.js에서 child_process 등을 이용해 호출

이미지 분석, 예측 모델 같은 AI 연산 전용

--------------------------------------------------------------------------------------------

7. routes

역할: URL(엔드포인트)과 컨트롤러 매핑

클라이언트가 /users, /posts 같은 API 요청 시 어떤 컨트롤러로 보낼지 정의

--------------------------------------------------------------------------------------------

8. services

역할: 비즈니스 로직 담당 (컨트롤러와 모델 중간 계층)

컨트롤러는 단순히 요청/응답만 담당 → 복잡한 로직은 서비스 계층에서 수행

예: 여러 모델을 조합한 로직, 데이터 검증, 외부 API 호출

--------------------------------------------------------------------------------------------

9. utils

역할: 프로젝트 전반에서 재사용 가능한 유틸리티 함수

포맷 변환, 공통 검증 함수, 날짜 처리, 세션 헬퍼 등

--------------------------------------------------------------------------------------------

10. server.js

역할: 서버의 진입점(Entry Point)

Express 앱 초기화, 미들웨어 등록, 라우트 연결, 서버 실행
